# Nap letiltása foglalásra — Implementációs jegyzet

> Ez egy kis méretű, egy sessionben megvalósított feature; a teljes lépésenkénti terv
> helyett itt a tényleges változtatások összefoglalója, a specnek
> (`docs/superpowers/specs/2026-08-23-block-day-design.md`) megfelelően.

## Elvégzett változtatások

- **`firestore.rules`**: új `blockedDays/{dayId}` szabály blokk — bárki olvashatja,
  csak bejelentkezett admin hozhatja létre/törölheti, update tiltva.
- **`foglalas.html`**: a `subscribeMonth()` mostantól a `slots` mellett a látható hónap
  `blockedDays` bejegyzéseit is élőben figyeli (`onSnapshot`); a `dayHasFreeSlot()`
  letiltott napra `false`-t ad vissza, így a naptárban inaktívként jelenik meg.
- **`admin.html`**:
  - új import: `setDoc`, `serverTimestamp`
  - `blockedDays` cache betöltve `loadBlockedDays()`-szal bejelentkezéskor
  - naptár napjai `.blocked` CSS osztályt kapnak, ha le vannak tiltva (csíkozott jelzés)
  - napra kattintáskor megjelenő `#blockDayBtn` gomb: letilt / felold, foglalás-számmal
    megerősítő ablakkal letiltás előtt, ha van már foglalás az adott napon

## Fontos: kézi lépés Firebase-ben

A `firestore.rules` fájl **nem deployol automatikusan** — ez csak egy dokumentum a
repóban, amit kézzel kell bemásolni. Firebase Console → Firestore Database → Rules fül →
illeszd be a `firestore.rules` teljes, frissített tartalmát → Publish. E nélkül a
`blockedDays` írása/olvasása a Firestore szabályai miatt el fog bukni.

## Ellenőrzés

- `node` script-cel ellenőrizve, hogy a `<script>` tagek száma nyitva/zárva egyezik
  mindkét módosított HTML fájlban (nincs törött markup).
- Élő böngészős ellenőrzés a felhasználó felelőssége deploy után: admin.html-ben egy nap
  letiltása, majd foglalas.html-en ellenőrzés, hogy az a nap inaktívvá válik.
